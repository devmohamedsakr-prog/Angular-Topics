# Templates & Binding Interview Questions - Part 2.5: Two-Way Binding

## Two-Way Binding with ngModel

### Q1: What is two-way binding and how does it work?

**A:** Two-way binding synchronizes data in both directions:
- **Template → Component** - When user enters data
- **Component → Template** - When component property changes

```typescript
import { FormsModule } from '@angular/forms';

export class MyComponent {
  username = '';
}
```

```html
<input [(ngModel)]="username" />
<p>You entered: {{ username }}</p>
```

How it works:
1. User types in input → `username` property updates
2. Component code changes `username` → input updates
3. Both stay in sync automatically

---

### Q2: What's the difference between [(ngModel)] and [ngModel]?

**A:**
- **[ngModel]** - One-way binding (component → template only)
- **[(ngModel)]** - Two-way binding (bidirectional)

```html
<!-- One-way: component to template -->
<input [ngModel]="username" />
<!-- User input doesn't update username -->

<!-- Two-way: bidirectional -->
<input [(ngModel)]="username" />
<!-- User input updates username, and vice versa -->

<!-- Equivalent to two-way -->
<input [ngModel]="username" (ngModelChange)="username = $event" />
```

Use `[ngModel]` when you only need to display. Use `[(ngModel)]` for synchronization.

---

### Q3: Do you need FormsModule for ngModel?

**A:** Yes, `ngModel` requires `FormsModule` to be imported.

```typescript
import { NgModule } from '@angular/core';
import { FormsModule } from '@angular/forms';

@NgModule({
  declarations: [MyComponent],
  imports: [FormsModule]  // Required!
})
export class MyModule {}
```

Or in standalone components:

```typescript
@Component({
  selector: 'app-form',
  standalone: true,
  imports: [FormsModule],  // Required!
  template: `<input [(ngModel)]="name" />`
})
export class FormComponent {
  name = '';
}
```

Without FormsModule, you'll get an error: "Can't bind to 'ngModel' since it isn't a known property of 'input'"

### Q4: What input types work with ngModel?

**A:** `ngModel` works with various input types:

```html
<!-- Text -->
<input type="text" [(ngModel)]="text" />

<!-- Number -->
<input type="number" [(ngModel)]="age" />

<!-- Email -->
<input type="email" [(ngModel)]="email" />

<!-- Password -->
<input type="password" [(ngModel)]="password" />

<!-- Checkbox -->
<input type="checkbox" [(ngModel)]="agree" />

<!-- Radio -->
<input type="radio" value="option1" [(ngModel)]="selected" />

<!-- Textarea -->
<textarea [(ngModel)]="message"></textarea>

<!-- Select -->
<select [(ngModel)]="selectedCountry">
  <option value="usa">USA</option>
</select>
```

### Q5: How do you detect ngModel changes?

**A:** Use `(ngModelChange)` event to detect when the value changes.

```typescript
export class MyComponent {
  username = '';
  changeLog: string[] = [];

  onUsernameChange(newValue: string) {
    console.log('Username changed to:', newValue);
    this.changeLog.push(newValue);
  }
}
```

```html
<input [(ngModel)]="username" (ngModelChange)="onUsernameChange($event)" />

<ul>
  <li *ngFor="let change of changeLog">{{ change }}</li>
</ul>
```

You can also validate or perform side effects when the value changes.

### Q6: What's ngModelGroup and when do you use it?

**A:** `ngModelGroup` groups related form fields together for organization and structure.

```typescript
export class AddressFormComponent {
  user = {
    name: '',
    address: {
      street: '',
      city: '',
      country: ''
    }
  };
}
```

```html
<form (ngSubmit)="onSubmit()">
  <!-- Personal info -->
  <fieldset ngModelGroup="personal">
    <input [(ngModel)]="user.name" name="name" placeholder="Name" />
  </fieldset>

  <!-- Address group -->
  <fieldset ngModelGroup="address">
    <input [(ngModel)]="user.address.street" name="street" placeholder="Street" />
    <input [(ngModel)]="user.address.city" name="city" placeholder="City" />
    <input [(ngModel)]="user.address.country" name="country" placeholder="Country" />
  </fieldset>

  <button type="submit">Submit</button>
</form>
```

Use `ngModelGroup` to:
- Organize related fields
- Group validation
- Better form structure

### Q7: How do you validate with ngModel?

**A:** You can validate by checking the value and controlling button state.

```typescript
export class FormComponent {
  email = '';

  isValidEmail(): boolean {
    const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
    return emailRegex.test(this.email);
  }

  submit() {
    if (this.isValidEmail()) {
      console.log('Valid email');
    } else {
      console.log('Invalid email');
    }
  }
}
```

```html
<input [(ngModel)]="email" placeholder="Email" />

<p *ngIf="!isValidEmail() && email" class="error">
  Invalid email format
</p>

<button (click)="submit()" [disabled]="!isValidEmail()">
  Submit
</button>
```

### Q8: Can you reset a form with ngModel?

**A:** Yes, reset the model to original values.

```typescript
export class FormComponent {
  formData = {
    firstName: '',
    lastName: '',
    email: ''
  };

  // Store original values
  originalData = { ...this.formData };

  resetForm() {
    this.formData = { ...this.originalData };
  }
}
```

```html
<form (ngSubmit)="onSubmit()">
  <input [(ngModel)]="formData.firstName" name="firstName" />
  <input [(ngModel)]="formData.lastName" name="lastName" />
  <input [(ngModel)]="formData.email" name="email" />

  <button type="submit">Submit</button>
  <button type="button" (click)="resetForm()">Reset</button>
</form>
```

### Q9: What's the difference between [(ngModel)] and FormControl?

**A:**
- **[(ngModel)]** - Simple, template-driven, good for quick forms
- **FormControl** - Reactive, programmatic, good for complex forms

```typescript
// Template-driven
export class TemplateComponent {
  username = '';
}
```

```html
<input [(ngModel)]="username" />
```

```typescript
// Reactive
import { FormControl } from '@angular/forms';

export class ReactiveComponent {
  username = new FormControl('');
}
```

```html
<input [formControl]="username" />
```

**Use template-driven for:**
- Quick prototypes
- Simple forms
- Few fields

**Use FormControl/FormGroup for:**
- Complex forms
- Validation
- Dynamic fields
- Reusable form logic

### Q10: When should you NOT use ngModel?

**A:** Avoid `ngModel` in these situations:

1. **Complex forms** - Use ReactiveFormsModule instead
```typescript
// Bad
<input [(ngModel)]="field1" />
<input [(ngModel)]="field2" />
<!-- Many more fields -->

// Good
form = this.fb.group({
  field1: ['', Validators.required],
  field2: ['', Validators.required]
});
```

2. **Performance-critical apps** - ReactiveFormsModule is more efficient
3. **Dynamic fields** - Harder to manage with ngModel
4. **Cross-field validation** - Better with Reactive Forms
5. **Async validation** - Use ReactiveFormsModule

### Q11: Can you use ngModel with custom components?

**A:** No, `ngModel` doesn't work with custom components. Create custom two-way binding instead.

```typescript
// ❌ WON'T WORK
<app-counter [(ngModel)]="count"></app-counter>

// ✅ USE @Input @Output INSTEAD
@Component({
  selector: 'app-counter',
  template: `...`
})
export class CounterComponent {
  @Input() count: number = 0;
  @Output() countChange = new EventEmitter<number>();
}

// Usage
<app-counter [(count)]="myCount"></app-counter>
```

Custom components need matching `@Input` / `@Output` names to support two-way binding.

### Q12: What are common ngModel mistakes?

**A:**

1. **Forgetting name attribute** - Required in forms
```html
<!-- ❌ BAD -->
<input [(ngModel)]="value" />

<!-- ✅ GOOD -->
<input [(ngModel)]="value" name="myInput" />
```

2. **Forgetting FormsModule**
```typescript
// ❌ BAD - FormsModule not imported
imports: [CommonModule]

// ✅ GOOD
imports: [CommonModule, FormsModule]
```

3. **Using with complex objects inefficiently**
```typescript
// ❌ BAD - entire object recreated
<input [(ngModel)]="user.profile.name" />

// ✅ GOOD - pre-computed property
user = { profile: { name: 'John' } };
// Access via property
```

4. **No validation**
```html
<!-- ❌ BAD - no validation -->
<input [(ngModel)]="email" />

<!-- ✅ GOOD - validate -->
<input [(ngModel)]="email" (ngModelChange)="validateEmail($event)" />
```

## Key Takeaways

✅ Two-way binding `[(ngModel)]` synchronizes bidirectionally
✅ Requires `FormsModule` import
✅ One-way `[ngModel]` + event = equivalent to `[(ngModel)]`
✅ Use `(ngModelChange)` to detect changes
✅ `ngModelGroup` organizes related fields
✅ Validate by checking values and disabling buttons
✅ Can reset forms by updating model
✅ Use Reactive Forms for complex scenarios
✅ Always include `name` attribute on form inputs
✅ Custom two-way binding uses `@Input` + `@Output`
